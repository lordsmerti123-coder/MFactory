# Подключение локальной модели к Оракулу

Как запустить YandexGPT-5-Lite-8B-instruct локально через `llama-cpp-python`
и подключить его к ИИ-помощнику.

Проверено на Windows с видеокартой NVIDIA (12 ГБ VRAM, compute capability 12.0).

---

## Коротко

Модель работает через `llama-cpp-python`: библиотека загружает GGUF-файл
и считает ответы на видеокарте.

Главная сложность — **согласовать версии CUDA**. Установленный пакет может
быть собран под одну версию CUDA, а в системе стоять другая. Тогда
`import llama_cpp` падает с ошибкой:

```
RuntimeError: Failed to load shared library 'llama.dll':
Could not find module 'llama.dll' (or one of its dependencies).
```

Причина не в самом `llama.dll`, а в его зависимостях. Решение — положить
рядом нужные библиотеки CUDA-рантайма (см. ниже).

---

## Проверка работы

```powershell
venv\Scripts\python.exe run_yandexgpt.py --prompt "Для чего нужна токенизация?"
```

При успешной загрузке в выводе появится строка о найденном устройстве:

```
ggml_cuda_init: found 1 CUDA devices (Total VRAM: 12226 MiB)
```

---

## Если `import llama_cpp` не работает

### Как понять, какой CUDA-рантайм нужен

Посмотрите, какие библиотеки требует `ggml-cuda.dll`. Ошибка обычно называет
недостающий файл: например, сборка ждёт `cudart64_12.dll` и `cublas64_12.dll`
(это CUDA 12), а в системе стоит CUDA 13 с файлами `cudart64_13.dll`.

### Решение

Положите библиотеки CUDA-рантайма нужной версии в папку пакета:

```
venv\Lib\site-packages\llama_cpp\lib\
```

| Файл | Размер |
|---|---|
| `cudart64_12.dll` | ~0.6 МБ |
| `cublas64_12.dll` | ~113 МБ |
| `cublasLt64_12.dll` | ~692 МБ |

Их можно взять из любого CUDA Toolkit той же major-версии, папка `bin`
или `bin\x64`.

После этого `import llama_cpp` заработает, и модель загрузится на видеокарту.

## Настройки модели

Из карточки `yandex/YandexGPT-5-Lite-8B-instruct(-GGUF)`:

- архитектура `llama`, 8B параметров, контекст 32k токенов, квантование `Q4_K_M`;
- **нестандартный шаблон диалога**: модель генерирует одну реплику после
  последовательности `Ассистент:[SEP]`, завершая её токеном `</s>`;
- **нестандартная токенизация**: рекомендуется оригинальный sentencepiece,
  каждая реплика токенизируется отдельно, `\n` заменяется на `[NL]`;
- рекомендуемые параметры: `temperature=0.3`, `top_p=0.9`, `max_tokens=1024`.

**Практический вывод для llama.cpp:** шаблон `Ассистент:[SEP]` / `</s>`
уже зашит в GGUF (`tokenizer.chat_template`, BOS=1, EOS=2), поэтому
достаточно обычного `create_chat_completion`. Ручная подстановка `[NL]`
не нужна.

## Скорость

| Запрос | Время ответа |
|---|---|
| «Для чего нужна токенизация?» (96 токенов) | 1.6 сек |
| «Напиши короткое стихотворение о Москве» | 2.9 сек |

Загрузка модели со всеми слоями на видеокарте (`n_ctx=4096`) — около 2.5 сек.

Первый запуск после установки может быть заметно медленнее: идёт однократная
компиляция ядер под конкретную видеокарту. Последующие ответы быстрые.

## Известные особенности

**Зависание инференса.** Иногда генерация может «зависнуть» и занять всю
память. В настройках Оракула есть таймаут (`ORACULUM_LOCAL_GEN_TIMEOUT`),
и модель помечается зависшей — последующие вызовы отклоняются до перезагрузки.

**Консоль и кириллица.** В консоли Windows русский текст может отображаться
нечитаемо. В `run_yandexgpt.py` это решено принудительным переключением
потоков на UTF-8. В самом интерфейсе программы текст отображается корректно.

**Сборка из исходников.** Собственная сборка `llama.cpp` на новых
видеокартах (Blackwell) может падать после инициализации CUDA. Поэтому
используется готовая сборка `llama-cpp-python`, которая эти карты
уже поддерживает.

## Порядок действий на новой машине

1. Установить `llama-cpp-python` (см. `requirements.txt`).
2. Проверить, что `import llama_cpp` работает:

   ```powershell
   venv\Scripts\python.exe -c "import llama_cpp; print('ok')"
   ```

3. Если падает — посмотреть в ошибке имя недостающего файла и положить
   библиотеки CUDA-рантайма той же версии в `venv\Lib\site-packages\llama_cpp\lib\`.
4. Скачать GGUF-модель и положить в папку проекта.
5. Запустить программу — Оракул найдёт модель и начнёт её использовать.
