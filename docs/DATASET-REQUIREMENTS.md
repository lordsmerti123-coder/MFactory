================================================================================
ХАРАКТЕРИСТИКИ И ТРЕБОВАНИЯ К ДАТАСЕТАМ ДЛЯ АРХИТЕКТУР ПРОГРАММЫ
================================================================================

Здесь описано, какой датасет нужен для каждой архитектуры из «зоопарка»
программы: тип данных, формат записей, минимальный и рекомендуемый размер,
особые требования. Датасеты загружаются из формата .oai (DatasetContainer)
или создаются встроенным генератором (вкладка «Генератор»).

--------------------------------------------------------------------------------
ОБЩИЕ ТРЕБОВАНИЯ КО ВСЕМ ДАТАСЕТАМ
--------------------------------------------------------------------------------
• Файл — формат .oai (DatasetContainer, формат версии 2.0). Обязательно
  наличие полей meta (data_type, task_type) и данных (samples/features).
• Датасет должен соответствовать DataType архитектуры (проверяется при
  создании модели, см. матрицу совместимости core/model_factory.py).
• Желательно разделение на train/test (обычно 80/20). Без тестового набора
  программа выдаст предупреждение о возможном переобучении.
• Числовые признаки желательно нормализовать (стандартизация к нулю/единице),
  изображения — привести к диапазону [0,1].
• Для текстов нужен словарь минимум из 4 служебных токенов:
  PAD, UNK, BOS, EOS. Словарь строится автоматически при разбиении данных.
• Для изображений обязательно указание image_shape (H, W, C) в конфиге модели.
• Тексты и последовательности внутри одного датасета желательно выравнивать
  по длине (padding), иначе обучение замедляется и теряется точность.
• Чем меньше датасет, тем больше должно быть эпох и меньше batch_size.
  Ориентир: 200 эпох для 1000 примеров, 50–100 эпох для 10000+ примеров.

--------------------------------------------------------------------------------
СТАТУСЫ АРХИТЕКТУР
--------------------------------------------------------------------------------
  full     — полная реализация, обучается в обычном режиме.
  stub     — заглушка: создаётся упрощённая модель, выводится предупреждение.
  planned  — запланирована, кнопка создания модели неактивна.
Статус влияет на то, «поверит» ли программа обучению: для stub-архитектур
требования к датасету те же, но результат обучения — приблизительный.

================================================================================
1. 🟢 БАЗОВЫЕ АРХИТЕКТУРЫ
================================================================================

--------------------------------------------------------------------------------
1.1. MLP — Многослойный перцептрон (full)
--------------------------------------------------------------------------------
Тип данных:     numeric (таблицы и числа).
Задачи:         классификация, регрессия.
Формат записей: вектор чисел X (одинаковой длины D у всех примеров) + метка Y
                (класс или число).
Минимальный:    200–500 примеров (можно меньше для простых задач, напр. XOR).
Рекомендуемый:  1000–10000 примеров.
Особенности:    вход фиксированной размерности; у всех примеров одинаковое
                число признаков. Подойдут задачи генератора: xor_problem,
                function_approximation, regression_linear, clustering_blobs
                (для кластеризации — без меток).
Требования:     нормализация признаков обязательна для быстрой сходимости.

--------------------------------------------------------------------------------
1.2. CNN — Свёрточная сеть (full)
--------------------------------------------------------------------------------
Тип данных:     image; также audio и time_series (1D-CNN по спектрограммам).
Задачи:         классификация изображений, классификация звука/рядов.
Формат записей: изображения (H, W, C) + метка класса; для аудио — спектрограмма
                или волна (длина, каналы) + метка.
Минимальный:    500–1000 изображений на класс.
Рекомендуемый:  3000–10000+ на класс.
Особенности:    все изображения одного размера. Примеры генератора:
                shapes_2d, shapes_3d, mnist_like, color_classification,
                tone_classification, chord_recognition.
Требования:     в конфиге обязательно image_shape (H, W, C); пиксели [0,1].

--------------------------------------------------------------------------------
1.3. RNN — Рекуррентная сеть (full)
--------------------------------------------------------------------------------
Тип данных:     text, numeric, time_series, audio.
Задачи:         seq2seq, классификация последовательностей, регрессия по ряду.
Формат записей: последовательность токенов/чисел одинаковой длины (или с
                выравниванием) + целевая последовательность или метка.
Минимальный:    1000 примеров.
Рекомендуемый:  5000–50000 примеров.
Особенности:    плохо запоминает длинные последовательности — длина примеров
                не должна быть большой (ориентир до 30–50 шагов).
                Подходят задачи: reverse_string, cipher_caesar, sine_wave,
                trend_prediction.

--------------------------------------------------------------------------------
1.4. LSTM — Долгая краткосрочная память (full)
--------------------------------------------------------------------------------
Тип данных:     text, numeric, time_series, audio.
Задачи:         seq2seq, классификация, регрессия, прогнозирование рядов.
Формат записей: как у RNN, но лучше держит длинные последовательности.
Минимальный:    1000 примеров.
Рекомендуемый:  5000–50000 примеров.
Особенности:    рекомендована для математики, шифров, временных рядов.
                Примеры генератора: mixed_math, multiplication, ciphers,
                sine_wave, seasonal_pattern, trend_prediction.
Длина примера:  до 100–200 шагов.

--------------------------------------------------------------------------------
1.5. GRU — Быстрая рекуррентная (full)
--------------------------------------------------------------------------------
Тип данных:     text, numeric, time_series, audio.
Задачи:         те же, что у LSTM.
Формат записей: последовательности + цели, как у RNN/LSTM.
Минимальный:    1000 примеров.
Рекомендуемый:  5000–30000 примеров.
Особенности:    обучается быстрее LSTM, чуть хуже на очень длинных
                последовательностях. Подходит для тех же задач генератора.

--------------------------------------------------------------------------------
1.6. Transformer Seq2Seq (full)
--------------------------------------------------------------------------------
Тип данных:     text.
Задачи:         seq2seq: перевод, математика, шифры, генерация текста.
Формат записей: пара «входная строка → выходная строка». Примеры генератора:
                addition, subtraction, multiplication, division, mixed_math,
                linear_equation, quadratic, modular_arithmetic, prime_check,
                fibonacci, number_sequence, cipher_caesar, cipher_atbash,
                cipher_vigenere, reverse_string, word_sort, translation_pairs.
Минимальный:    2000 пар.
Рекомендуемый:  20000–100000+ пар.
Особенности:    требует много данных. Внимание (attention) связывает любые
                позиции — длина примеров до 100–200 токенов.
Требования:     vocab ≥ 4 (PAD, UNK, BOS, EOS); при обучении — паддинг и
                маскирование. embedding_dim должен делиться на num_heads.

--------------------------------------------------------------------------------
1.7. Transformer Encoder (full)
--------------------------------------------------------------------------------
Тип данных:     text; также time_series.
Задачи:         классификация текста (спам/не спам, тональность), анализ.
Формат записей: текст (последовательность токенов) + метка класса.
Минимальный:    1000–2000 примеров.
Рекомендуемый:  10000–50000 примеров.
Особенности:    только «чтение» входа без генерации. Подходят задачи:
                palindrome_check, prime_check и любые текстовые классификации.
Требования:     vocab ≥ 4, паддинг, embedding_dim % num_heads == 0.

--------------------------------------------------------------------------------
1.8. Transformer Decoder (planned)
--------------------------------------------------------------------------------
Тип данных:     text.
Задачи:         генерация текста (авторегрессия).
Формат записей: тексты (одна последовательность, без пары).
Минимальный:    5000 примеров.
Рекомендуемый:  50000+.
Особенности:    архитектура запланирована — создание модели пока недоступно.

2. 🎨 ГЕНЕРАТИВНЫЕ АРХИТЕКТУРЫ
================================================================================

--------------------------------------------------------------------------------
2.1. Autoencoder (full)
--------------------------------------------------------------------------------
Тип данных:     numeric, image.
Задачи:         очистка от шума, сжатие, поиск аномалий, восстановление.
Формат записей: X (вход, возможно зашумлённый) и цель = чистый X (та же
                размерность). Для шумоподавления — пары «шум → чисто».
Минимальный:    500 примеров.
Рекомендуемый:  5000–50000.
Особенности:    обучается без меток (self-supervised). Примеры: noise_denoise,
                function_approximation, clustering_blobs.
Требования:     вход и выход одинаковой размерности.

--------------------------------------------------------------------------------
2.2. VAE — Вариационный автоэнкодер (full)
--------------------------------------------------------------------------------
Тип данных:     numeric, image.
Задачи:         генерация новых данных, похожих на обучающие.
Формат записей: просто данные X (без меток), желательно большой объём.
Минимальный:    1000–2000 примеров.
Рекомендуемый:  10000–100000.
Особенности:    чем больше данных и разнообразия — тем реалистичнее генерация.
                Примеры: pattern_generation, mnist_like, clustering_blobs.
Требования:     нормализация данных (для картинок — [0,1]).

--------------------------------------------------------------------------------
2.3. CVAE — Условный VAE (full)
--------------------------------------------------------------------------------
Тип данных:     numeric, image.
Задачи:         генерация данных заданного класса (с условием).
Формат записей: X + метка класса Y (условие). Без меток модель выродится в VAE.
Минимальный:    1000–2000 примеров на класс.
Рекомендуемый:  10000+ на класс.
Особенности:    метка обязательно должна участвовать в обучении как условие.

--------------------------------------------------------------------------------
2.4. GAN — Генеративно-состязательная сеть (full)
--------------------------------------------------------------------------------
Тип данных:     numeric (в интерфейсе также image).
Задачи:         генерация реалистичных данных.
Формат записей: большой набор реальных данных X (без меток).
Минимальный:    1000–2000 примеров.
Рекомендуемый:  20000–100000.
Особенности:    GAN капризна к малым датасетам (нестабильное обучение,
                mode collapse). Примеры: pattern_generation, mnist_like,
                clustering_blobs.
Требования:     данные в диапазоне [-1, 1] (выход генератора — Tanh).

--------------------------------------------------------------------------------
2.5. DCGAN — Свёрточная GAN (full)
--------------------------------------------------------------------------------
Тип данных:     image.
Задачи:         генерация изображений.
Формат записей: изображения X (без меток), все одного размера.
Минимальный:    1000–2000 изображений.
Рекомендуемый:  20000–100000+.
Особенности:    стабильнее обычного GAN, но всё равно требует много данных.
                Примеры: pattern_generation, mnist_like, shapes_2d.
Требования:     image_shape в конфиге; изображения в [-1, 1].

--------------------------------------------------------------------------------
2.6. Diffusion — DDPM (stub)
--------------------------------------------------------------------------------
Тип данных:     image, numeric.
Задачи:         генерация изображений (пошаговый денойзинг).
Формат записей: изображения X (без меток).
Минимальный:    1000 изображений.
Рекомендуемый:  50000–500000 (нужно очень много данных и времени).
Особенности:    реализация упрощена (заглушка): модель учится как автоэнкодер,
                реального денойзинга пока нет. Результат — приблизительный.

--------------------------------------------------------------------------------
2.7. Latent Diffusion — LDM (stub)
--------------------------------------------------------------------------------
Тип данных:     image.
Задачи:         генерация изображений в латентном пространстве.
Формат записей: изображения X (без меток).
Минимальный:    1000 изображений.
Рекомендуемый:  50000+.
Особенности:    заглушка: реальный пайплайн (автоэнкодер + диффузия) не
                реализован, результат обучения — приблизительный.

--------------------------------------------------------------------------------
2.8. ConvAE — Свёрточный автоэнкодер (full)
--------------------------------------------------------------------------------
Тип данных:     image.
Задачи:         очистка от шума, сжатие, восстановление изображений.
Формат записей: пары «зашумлённое → чистое» (X, X_clean) или просто X.
Минимальный:    500–1000 изображений.
Рекомендуемый:  5000–50000.
Особенности:    пример генератора: noise_denoise (изображения).
Требования:     image_shape (H, W, C); картинки [0,1] (выход — Sigmoid).

3.1. ViT — Vision Transformer (full)
--------------------------------------------------------------------------------
Тип данных:     image.
Задачи:         классификация изображений.
Формат записей: изображения X + метка класса.

Минимальный:    1000–2000 изображений на класс.
Рекомендуемый:  20000+.
Особенности:    глубокая сеть со skip-connections; стандарт для классификации.
                Примеры: shapes_2d, shapes_3d, mnist_like, color_classification.

Рекомендуемый:  10000+.

Минимальный:    500–1000 графов.

Особенности:    заглушка: требует torch_geometric, сейчас — упрощённый MLP.

Минимальный:    500–1000 графов.
Рекомендуемый:  10000+.
Особенности:    заглушка (требуется torch_geometric). Учебный результат

Минимальный:    500–1000 графов.
Рекомендуемый:  10000+.
Особенности:    заглушка (требуется torch_geometric). Результат обучения
                приблизительный.

                regression_linear.

Задачи:         любые.
Формат записей: зависит от выбранной пользователем структуры модели.
Особенности:    совместимость не проверяется — за требования к данным отвечает
                сам пользователь.

================================================================================
СВОДНАЯ ТАБЛИЦА: ТИП ДАННЫХ → ПОДХОДЯЩИЕ АРХИТЕКТУРЫ
================================================================================
numeric      → MLP, Autoencoder, VAE, CVAE, GAN, RBFN, SOM, Diffusion,
               Spiking NN, PINN, Neural ODE, RNN, LSTM, GRU, Custom
text         → Transformer Seq2Seq, Transformer Encoder, Transformer Decoder,
               RNN, LSTM, GRU, Custom
image        → CNN, ViT, ResNet, CapsNet, DCGAN, ConvAE, Autoencoder, VAE,
               CVAE, Diffusion, Latent Diffusion, CNN_RNN, Custom
audio        → CNN (спектрограммы), RNN, LSTM, GRU, Custom
time_series  → RNN, LSTM, GRU, Transformer Encoder, Liquid NN, Spiking NN,
               PINN, Neural ODE, CNN (1D), Custom
graph        → GNN, GCN, GAT, Graph Transformer, Custom
multimodal   → CNN_RNN, CLIP-like, Custom

================================================================================
ПАМЯТКА ПО РАЗМЕРАМ (общие ориентиры для учебных задач)
================================================================================
  Простые задачи (XOR, линейная регрессия, малые функции):  200–2000 примеров
  Классификация / регрессия средняя (фигуры, тональность):  1000–20000
  Seq2seq / тексты (математика, шифры):                    2000–50000
  Генеративные модели (GAN, VAE, Diffusion):               10000–100000+
  Видео/мультимодальные / большие трансформеры:            50000+

Если точность не растёт:
  • данных слишком мало → увеличить датасет (генератор) или добавить
    аугментацию (шум, сдвиги, перевороты для изображений);
  • задачи сложнее архитектуры → сменить архитектуру (см. рекомендации Оракула);
  • признаки не нормализованы → нормализовать.
